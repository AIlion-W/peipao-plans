一、先建立对 AI 的正确认知

你们做企业周边的核心能力，是把一个客户的 brief 拆成"选品—设计—打样—生产—结案"一条条可复用的动作。用 AI 也是同一回事：把每个重复动作教会一个"新员工"，让它先跑通一个动作，再把动作串成生产线。这两个月最该警惕的，恰恰是这次执行-002 暴露的弯路——一上来就想搭"全公司中台"，摊子铺太大、单个改动吃掉一半 token，做了很多却没有一个真正落地验证。节奏铁律：一个场景一个场景跑通，先把一件事落地掉。

二、要搭建的 3 个智能体（按首战板块优先级）

排序原则来自执行-002 的共识：先挑"最耗人力、重复性最高、最纯手活、判断标准最清晰"的场景——也就是执行岗的订单/物流处理（数据源明确、Codex 舒适区），它们已有跑通的雏形，最容易在业务上验证提效。设计岗的品牌策划智能体（001 主线）并行推进。

① PO / 出货单处理智能体

痛点：洋洋/Aki 每次做库存单，要从几百条 SKU 总表里一条条人工筛出这 50 条，再按工厂拆分下发——纯手活、极耗时。
角色设定：订单处理助手，以"成本总表"为唯一基准
输入：客户 PO（PDF）+ 成本总表
输出：识别 SKU → 总表筛选 → 出货单 / 多工厂合并下单表（自动剔除标灰下架品）
阶段 5W1-W3首战·已跑通

② 运费与箱规建议智能体

痛点：送不同品牌仓库有箱规要求，多家物流公司（顺丰/跨越）比价靠人工，慢且易错。
角色设定：物流核算助手
输入：产品 + 箱规 + 目的地仓库
输出：箱规倒推建议 + 物流公司官网询价比价（修好"点跨越跳顺丰"的链接 bug）
阶段 5W2-W4Edwin·已做出

③ 品牌策划智能体（设计岗·001 主线）

痛点：设计岗 3 人，提案丰富度受限，选品常"富士自己也能想到、不出彩"。
角色设定：品牌全案策划，懂客户行业 + 站客户角度
输入：客户 brief + 项目背景 + 案例库 + 联网搜索
输出：核心世界观 / 品牌洞察 / 视觉方向 / 选品推荐（充分上下文+反问+多轮迭代）
阶段 5-6W4-W6待拉回主线

三、把智能体打包成 Skill（执行岗人人能用，跨项目复用）

Skill 就是一个文档：你把跑通的流程让 Codex 整理封装，分享给同事后，他那边只要文件命名一致（都叫"成本总表"），他的 Codex 就能索引到——不必打包发原文件。封装好后，搭建期那种"改代码吃掉一半 token"也会大降，后期纯文字处理省很多。

Skill 1 · 出货单

触发词：/出货单
能力：丢 PO（PDF）→ 自动识别 SKU → 基于成本总表生成出货单 / 工厂下单表
复用：洋洋、Aki、所有执行岗同事，每个新订单一键跑

Skill 2 · 运费箱规

触发词：/运费箱规
能力：输入产品+目的地 → 箱规建议 + 物流比价
复用：跨品牌、跨项目通用，物流信息维护进知识层即可

Skill 3 · 策划案

触发词：/策划案
能力：brief → 全案策划（世界观/洞察/视觉/选品）
复用：3 名设计师共用，提案丰富度统一拉升

四、把 Skills 串成工作流，产出可交付的 HTML 报告

选执行岗最高频的"接单到下单"链路做示例——这是当前最纯手活、最该先自动化的一条线。先把单个 Skill 跑稳，再把它们顺序串起来。

工作流 · 接单到工厂下单（示例）
📄 客户 PO（PDF） → /出货单（识别 SKU + 总表筛选） → 多工厂拆单 → /运费箱规（比价） → 📊 HTML 报告生成器 → 📧 推送相关人
交付物示例（HTML 报告）
· 本单 SKU 明细 + 按工厂拆分的下单表（标灰下架品已剔除）
· 各工厂数量 / 单价 / 行总额汇总
· 箱规建议 + 顺丰/跨越运费比价
· 库存预警（出货后低于安全库存的 SKU 高亮提示补货）
