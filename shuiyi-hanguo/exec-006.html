老板任务跟进 AI 助理：先用 Codex + 飞书跑半自动闭环

时间2026-07-06 15:25
时长56 分 24 秒
陪跑老师韩国
参会许忠煌、王鑫隆 Lion、林韦韩

本次会议干了什么

  1. 拆出新需求。许总想要一个“AI 助理 / 工作安排龙虾”，替代老板跟进每周销售报表、违规提醒、平台问题处理等日常任务。
  2. 把目标从“实时对话”降到“定时巡检”。先不追求像人一样实时聊天，改成 Codex 定时扫任务表 / 群消息，判断完成状态并推送提醒或日报。
  3. 明确飞书是更合适的自动化中台。企业微信开放度不够，飞书的 Lark Skill、多维表格、消息、日历和知识库更适合先跑试点。
  4. 压住工具诱惑。小龙虾、Hermes、N8N、Dify 都不是第一步；没有角色、流程、规则和完成标准，换工具只会增加维护成本。
  5. 把 AI 助理拆成业务规则。任务从哪里来、谁负责、何时交付、怎么反馈、什么算完成、超时怎么上报，要先写成 AI 能执行的机械流程。
  6. 同步图片 / 视频进展。评价图智能体已有可用结果；主图 / 详情图继续以即梦为主；视频线仍薄弱，后续另约张航波跟进。
关键判断先用流程替代“思考”。AI 不是先变成老板，而是先按老板已经写清的规则巡检、提醒、汇总。

本周核心决策

节奏铁律不要从“全自动代理”开始；先用 Codex + 飞书把一个任务跟进场景跑成半自动闭环。
首个试点
从每周销售报表登记或违规提醒处理二选一，不一开始覆盖全公司所有任务。
系统载体
飞书测试群 / 多维表格作为任务载体，字段包含来源、责任人、截止时间、状态、证据、下次提醒和上报对象。
运行机制
Codex 定时巡检任务表 / 群消息，按规则判断“完成 / 已完成 / 处理中 / 未完成”，再推送提醒或生成老板日报。
工具边界
小龙虾 / Hermes / N8N / Dify 暂不优先；流程和规则成熟后再评估是否需要更强代理。
部署边界
先在一台电脑上跑出手感，确认锁屏运行和定时任务稳定；云端部署、多电脑同步后置。
