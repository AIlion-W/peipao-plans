二、要搭建的 3 个智能体（按首战板块优先级）

执行-005 已经把当前顺序定死：先验收主图智能体，再用真实表格跑 Codex 比对，最后接实时金价看板与预测自动化。客服 QA 等需求继续保留，但不在当前三条主线上分散资源。

① 黄金主图裂变智能体 ▶ 当前验收

痛点：金豆、金条、小金珠的商品图普遍只放白底产品，规格、克重、成分和卖点常被埋在详情页；现有智能体尚未真实测试。
角色设定：贵金属电商视觉策划，能把产品属性和购买理由转成清晰主图。
输入：产品白底图、规格/克重/成分/卖点、参考图和平台要求。
输出：主图方案、生成图、可用/不可用判断和下一轮指令修改建议。
先验收阶段 3→4ChatGPT Plus / Image

② Codex 表格比对智能体

痛点：多系统表格需要人工理解字段、逐项比对和标记异常；不先提供真实规则，AI 无法稳定替代人工。
角色设定：贵金属业务数据核对员，严格按客户提供的字段关系和异常标准输出差异。
输入：真实表格、主键字段、表间关系、比对逻辑和人工判断样例。
输出：差异表、异常原因、待人工确认项和可复用的比对流程。
下一主线阶段 4→5Codex

③ 实时金价与预测助手

痛点：公开金价来源分散且实时变化；现有预测依赖临时提问和手工更新，无法积累历史效果。
角色设定：贵金属行情数据助手，只读取已确认的公开数据源并保留每次预测依据。
输入：融通金 / 上海黄金交易所等公开数据字段、刷新频率、预测因子和历史结果。
输出：实时看板、定时金价简报、预测记录和预测/实际偏差复盘。
数据分析跑通后阶段 5→6自动化 + HTML

三、把智能体打包成 Skill（SOP 是资产，员工换了照用）

现在要沉淀的不是某一次对话，而是三条可重复执行的业务能力：主图裂变、表格比对、金价简报。每个 Skill 都必须有固定输入、固定输出和人工验收点，不能把一次成功当成稳定流程。

Skill 1 · 主图裂变

触发词：/主图裂变
能力：输入产品白底图和属性资料，输出主图、卖点表达和业务验收清单
复用：更换产品资料和平台规则后，可服务不同黄金投资品与商户

Skill 2 · 表格比对

触发词：/表格比对
能力：按既定主键、字段映射和异常规则生成差异表与待确认项
复用：更换输入表和规则配置，可迁移到退差、结算、报价核对等场景

Skill 3 · 金价简报

触发词：/金价简报
能力：读取已确认数据源，生成行情快照、预测依据和历史偏差复盘
复用：固定数据字段与校验口径后，可定时生成 HTML 看板和内部简报

四、把 Skills 串成工作流，形成可复盘的金价看板

金价预测已经在人工使用，但现在是单次提问、单次生成，历史结果无法形成经验。下一阶段的价值不是「再做一个网页」，而是把数据采集、预测依据、实际结果和偏差复盘接成连续流程。

工作流示例 · 实时金价与预测复盘（数据分析跑通后启动）
公开数据源 → 固定字段采集 → /金价简报 → 预测与依据 → 实际结果校验 → HTML 看板
HTML 报告包含
当前金价与来源时间戳 · 影响因素与预测结论 · 历史预测记录 · 预测与实际偏差

启动条件
先用 Codex 跑通一份真实表格比对；再确认数据源可持续读取、目标字段和刷新频率；最后才接定时任务。

六、陪跑承诺

① 落地承诺
一块积木稳了再叠下一块。先让主图智能体真实可用，再进入表格比对；数据源和规则没有确认前，不承诺稳定实时采集。
② 复刻承诺
跑通的能力必须沉淀成输入模板、规则、Skill 和验收标准；换产品、换表格、换数据源时，仍有明确复用边界。
③ 员工承诺
客户执行团队负责提供业务规则与真实反馈，陪跑团队负责把方法固化；业务负责人只把控节奏，不亲自承担重复执行。
数据来源：面试、场景确认及历次执行会议；公开页面已删除客户名称、个人姓名、精确日期和内部资料定位信息。

陪跑团队判断：「客户当前不是缺方向，而是缺一次真实验收；先让现有智能体跑起来，再把真实数据规则交给 Codex，最后接实时看板。」
