二、要搭建的 3 个智能体（搭积木顺序）

花花在场景确认会上明确分工：南总学战略对话+数据分析（决策层），技术部学 Codex做实时金价（执行层）——老板不亲自执行。三个智能体按"从最小积木开始"顺序：南总个人激活 → Codex数据分析 → 技术部接金价。前两个跑通了，第三个就是技术部自学，陪跑方教学不单独收费。

① GPT 战略对话智能体

痛点：南总自述——"还没达到智能体的程度"，AI 体感为零；下面人推不动，因为老板自己不懂的事下面人不动（花花原话："你给我开发个微信 = 不合理需求"）。
角色设定：南总的战略思考搭子，懂 ToB 服务平台业务 + 行业新政（2025-11 税改）背景。
输入：南总的决策问题（业务方向 / 资源分配 / 套餐选型）。
输出：多方案对比 + 风险点 + 下一步操作建议——给南总做"决策辅助大脑"。
阶段 3-4W1-W2首战

② Codex数据分析智能体

痛点：克重维度合并对账靠 Excel 一个专员"电脑都带不动"；退差顶峰 1400 单/天/人；爆款分析没产出能力。
角色设定：多系统数据对账员，懂展厅 ERP / 云仓 / 客服系统 / 平台 SaaS 数据接口。
输入：多源 Excel（按需选对账 / 退差 / 爆款三选一作首跑）。
输出：克重维度合并报表 + 退差异常清单 + 爆款热销分析——南总能直接看决策。
阶段 4-5W3-W4

③ 实时金价接口（技术部交付）

痛点：黄金随上海金交所/伦敦金实时波动，店铺多了手动改价跟不上；之前对接 AI 公司被 API + 奇门资质卡死。

输入：上海金交所 / 伦敦金来源配置 + 跨店铺改价规则。
输出：实时金价数据 + 跨店铺自动改价触发——参考荣通金案例。
阶段 5W5-W6技术部

三、把智能体打包成 Skill（跨岗位、跨平台复用）

花花在场景确认会上定了一条铁律："老板不亲自执行"。Skill 就是让你不用做技术细节、只按一个按钮调用结果——南总你按 `/战略对话` 出决策建议，对账专员按 `/对账分析` 出合并报表，技术部按 `/实时金价` 自动改价。一套 Skill 跨展厅 ERP / 云仓 / 客服 / 多平台 SaaS 通用。

Skill 1 · 战略对话

触发词：/战略对话 <决策问题>
能力：套陪跑方"GPT 战略对话课"提示词模板，输出多方案对比 + 风险点 + 操作建议。
复用：业务决策 → 团队管理 → 套餐选型 → 行业新政应对，全场景通用。

Skill 2 · 对账分析

触发词：/对账分析 <Excel>
能力：Codex读多源 Excel → 克重维度合并 → 自动出退差异常清单 + 爆款分析。
复用：现有 20+ 家店铺通用；新政后量小阶段调试好，量起来直接 scale。

Skill 3 · 实时金价

触发词：/实时金价
能力：Codex computer use 取上海金交所/伦敦金，跨店铺自动改价。
复用：每个新接入平台店铺直接调用，技术部维护成本极低。

四、把 Skills 串成"周经营复盘"工作流，产出 ToB 商户看板

三个 Skill 各自跑能解决"今天对账 / 改价 / 决策"的点；串成"周经营复盘"工作流后，每周自动产出一份给 ToB 商户的销售看板——这就是南总野心里的"赋能商户加分项"，落到实处。
